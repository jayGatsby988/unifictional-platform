# MANHATTAN — photo → 3D remodel studio

Commercial web app for contractors: upload photos of a **kitchen, bathroom, or lot/exterior** (+ optional description / plans), get an explorable photoreal 3D twin in ~60s, swap materials/colours, and watch a line-item estimate update live. Photoreal renders come from AI image-edit models applied to the original photo (or to a screenshot of the 3D view).

## Stack (pinned, installed)
Next.js 16 (app router, `src/`), React 19, TypeScript, Tailwind v4 (`@theme` tokens in `src/app/globals.css`), three 0.185, @react-three/fiber 9, @react-three/drei 10, @react-three/postprocessing 3, zustand 5, zod 4, openai 7, @vercel/blob, framer-motion, lucide-react, gsap, lenis, nanoid, three-stdlib. **Do not add packages** — if you truly need one, list it in your final report instead.

## Architecture (single source of truth = `RoomSpec`)
- `src/lib/spec/types.ts` — domain contracts: `KitchenSpec | BathroomSpec | ExteriorSpec`, `Project`, `RenderJob`, `ScanJob`, `Estimate`, material **slots**.
- `src/lib/spec/schema.ts` — zod mirrors + `jsonSchemaFor(roomType)` (strict JSON schema for the vision model).
- `src/lib/spec/defaults.ts` — `defaultKitchen/Bathroom/Exterior()` + `HOUSE_TEMPLATES` (demo mode + analyzer fallback).
- `src/lib/materials/catalog.ts` — `CATALOG` (~250 materials), `materialsForSlot(slot)`, `SLOT_META`, `KITCHEN_SLOTS/BATHROOM_SLOTS/EXTERIOR_SLOTS`, `DEFAULT_SELECTIONS`. Each material has `pbr` (texture id from `public/textures/<id>/{diff,nor,arm}.webp`, colour, roughness…), `prompt` (phrase for photoreal prompts), `group`+`tier` (pricing).
- `src/lib/estimate/estimator.ts` — `calculateEstimate(spec, selections, settings, baseline?)` → `Estimate`; `groupLines()`. With a baseline it prices the room twice (current + as-found) and reconciles by line id; the three-argument call is still full mode. `pricebook.ts` has unit prices, `REGIONS`, `ALLOWANCES`, `AllowanceKey`.
- `src/lib/spec/hood.ts` — the hood vocabulary, pure and importable from server code: `HOOD_STYLES`, `HOOD_SHAPES`, `CANOPY_IN`, `CABINET_ABOVE`, `resolveHoodStyle/Shape`, `resolveCabinetAbove(a, hasRow)`, `runForHood`, `rowHeightIn`, `hoodCabinetBandIn`. The layout, the estimator, the fitter, the reconciler and the prompt all derive the same answer from here — never re-derive it.
- `src/lib/store/project-store.ts` — zustand `useProjectStore` (persist **version 5**; `migrateProject()` is exported pure so `scripts/check-store.ts` can drive it): `project` (photos, spec, `selections` slot→materialId, renders, scans, estimateSettings) + `ui` (selectedSlot, hoveredSlot, cameraMode `orbit|walk|photo`, quality, panel, analysisPhase…). Selectors: `useProject`, `useSelections`, `useSpec`, `useUI`.
- `src/lib/units.ts` — `ft()`, `inch()` (spec is imperial; scene is metric, 1 unit = 1 m), `fmtUSD`, `fmtRange`, `fmtFt`.

## 3D engine (`src/components/scene/`)
- `SceneCanvas.tsx` — `<SceneCanvas env="interior|exterior|studio" rig={CameraRig}>` sets up renderer (ACES, shadows), HDRI env, post (N8AO, bloom, outline-on-select, SMAA, vignette), orbit/walk controls. `interiorRig(wFt,dFt,hFt)` / `exteriorRig(...)` helpers. `captureViewport()` → JPEG blob.
- `materials.ts` — `useSlotMaterial(slot)` (material follows the project's selection for that slot), `useCatalogMaterial(id)`, `utilMaterial('glass'|'chrome'|'porcelain'|…)`, `tintedMetal(hex)`. Materials are shared & cached; textures tile in world space.
- `geometry.ts` — **UVs are in meters**: use `worldBox(w,h,d)`, `worldPlane`, `bevelBox` (counters), `wallFace(length,h,holes)` (single-sided wall so an orbiting camera sees in = dollhouse), `wallFrame/onWall/wallPlacement` (room coordinate conventions — read the doc comment), `roofGeometry`, `shakerDoorParts`, `applyWorldUVs` for any custom geometry.
- `Surface.tsx` — `<Surface slot="countertop" geometry={...} position rotation/>`: mesh whose material is the slot's current selection; hover/click selects the slot in the store and outlines it. `<Prop util="chrome" geometry/>` for fixed props. Use `inert` for tiny trim.
- `Lighting.tsx` — `<InteriorRig w d h windows recessed colorTempK naturalLight/>`, `<ExteriorRig timeOfDay/>`, `PendantLight`, `RecessedLight`, `UnderCabinetStrip`, `WindowLight`.
- Room builders live in `scene/kitchen/KitchenScene.tsx`, `scene/bathroom/BathroomScene.tsx`, `scene/exterior/ExteriorScene.tsx` — each exports `<XScene spec={...}/>` (geometry + its own lighting rig, NO Canvas) and `xRig(spec): CameraRig`.

## Photo fidelity pipeline (the part that makes the twin THEIR kitchen)
- `src/lib/ai/prompt.ts` — analysis prompt: measurement playbooks, PROPORTIONS-first (ratios written to `detected.notes`), FINISHES (one `FinishObservation` per slot: family, daylight hex, accent, pattern, sheen, module), DÉCOR (shelves, plants, art, rug, window treatment, stools, counter styling), per-run `backsplash` + `backsplash.behindRange`, hood shape / per-appliance `bodyFinish` / `cabinetAbove` (what sits on the hood canopy: doors | glass | panel | none, null = by hood style — the vocabulary lives in `src/lib/spec/hood.ts`, imported by the layout, the estimator, the reconciler, the prompt, the LayoutPanel and the fitter). `src/lib/ai/inventory.ts` — a parallel vision call that boxes every visible element (`detected.elements`, normalised `{x0,y0,x1,y1}`, origin top-left).
- `src/lib/materials/match.ts` + `color.ts` — `matchFinish` scores the catalog by Lab ΔE / family / pattern / module; below the threshold it synthesises a deterministic `custom-<slot>-<hash>` material with the photo's colours on a per-family procedural recipe (`registerMaterial` in catalog.ts). `ensureSpecMaterials(spec)` regenerates + heals ids anywhere a spec enters (store, share page, analyze/refine/render/fit routes); `unifyRelatedSlots` keeps base/upper/tall cabinets consistent.
- `src/lib/fit/` — `fitToPhoto(spec, { aspect })`: projects the twin's element AABBs (`boxes.ts`, derived from the pure layouts) through a pinhole camera (`camera.ts`; yaw 0 = looking at the back wall, pitch positive = down, VERTICAL fov) and coordinate-descends camera + spec fields until they land on `detected.elements`. Result: `detected.camera.solved`, a mean-IoU score, matched/unmatched lists. Gated: spec edits only when they beat the original spec through the solved camera. Exposed as `POST /api/fit`; the refine route re-fits after corrections.
- **The cabinet above the hood** (`appliances[].cabinetAbove: 'none'|'doors'|'glass'|'panel'|null`). When a hood sits under a row of wall cabinets, the band between the canopy top and `run.upperTop` is a real `hood-cabinet` upper on the `cabinets_upper` slot — clickable, swappable and priced — and the hood unit ends at its underside, so no duct cover is drawn behind it. A band under 9" is drawn as a plain panel whatever the word says; under 4" nothing is drawn. `null` derives from the hood style via `resolveCabinetAbove`. **One box convention, three consumers:** the *hood* box is the canopy plus only the VISIBLE duct cover (`hoodExtents(a).top`); a cabinet on the canopy belongs to the *upper-cabinet-run* box, which therefore runs continuously across the hood. `boxes.ts`, `prompt.ts BOX_RULES` and `check-kitchen` §9 all say this — change one and change all three.
- **Seven proportion degrees of freedom**, written by the analyzer, searched by the fitter, drawn by `layout.ts`: `backsplash.heightIn` (numeric, overrides the category everywhere including behind the hood), `island.endPlacement` / `endOverhangIn` / `stoolOffsetIn` (at ≥ 6" of end overhang the end stools tuck UNDER the top), `lighting.pendants.positions` (explicit hooks, may hang past the island; the reconciler nulls them whenever `count` disagrees), `runs[].uppers[].heightIn`, `runs[].tall[].toCeiling`, `countertop.overhangIn`. The last two-depth pair is LayoutPanel- and fitter-only: the refine path grammar takes exactly one `[]` index.
- **The detail layer**: `decor.items` (24 max, 30 kinds) and `decor.cabinetContents` (10 max), solved into `KDecor.items` by `layout.ts buildDecor`/`solveItems` and drawn by `scene/kitchen/items.ts` + `contents.ts`. Everything it emits is a `prop()` with **no slot**, so the estimate is byte-identical with and without it (asserted in `check-decor` §7). `items.ts` owns the shape tables (`ITEM_PROPORTIONS`, `DEFAULT_SIZE_IN`, `SIZE_RANGE_IN`) and `layout.ts` imports them. `KItem.w` is ONE object — a row is `count` instances at a 1.1× pitch and the lane reserved `rowW`. Every host caps an item's height against its own headroom (a counter item is shortened to clear the wall cabinets and the hood above it, with a warning); nothing is ever dropped silently — `KDecor.warnings` names it. The `item` element cap is **90** and lives in four places that move together: `schema.ts DetectionMetaZ.elements`, `reconcile.ts MAX_ELEMENTS`, `inventory.ts MAX_INVENTORY_ELEMENTS` and the fitter's `cleanElementsDetailed`.
- **Proportions**: `report.ts proportionError` is a second, independent number — how right the twin's *shape ratios* are, as against `Photo match`, which is where the boxes land. It is weighted λ = 0.25 in the LOSS only, **never** in the pairing cost. The studio shows both (`Photo match NN% · Proportions NN%`) and never under one label. The inventory runs 3 concurrent passes merged by per-edge **median** (a mean lets one bad pass drag an edge) plus a concurrent items-only pass merged by `mergeItemPass`, and stores `detected.inventory { samples, agreement }` — server-owned, the analyzer must leave it null.
- **Baseline pricing** — `project.baseline` (`{ spec, selections, capturedAt, source }`) + `estimateSettings.mode: 'changes'|'full'`. In changes mode every line carries `scope` (changed | added | unchanged | removed), `baselineQty`, `fullTotal*` and a `reason`, allowances are scaled by a per-trade gate and floor (nothing changed → no allowance line at all), and an untouched twin opens at **$0** instead of quoting a whole remodel. `Estimate` carries the in-scope totals at the top level and the full-remodel block in `.full`. **Effective mode is `baseline ? mode : 'full'`**, so legacy three-argument calls, the landing page and pre-baseline shares are unaffected and full mode stays byte-identical to the old numbers. `captureBaseline(source)` stores the SAME spec object as `project.spec`; that reference equality is how `useAnalysis` knows the user has not started designing yet.
- `src/lib/ai/refine.ts` — pure `applyCorrections(spec, modelOutput, opts)` behind a typed allowlist (scalars, add/remove ops validated with the zod element schemas, camera fields, finishes observations); passes: camera → audit → diff → PROPORTIONS → DÉCOR → FINISHES. `useAnalysis.runAccuracyPass` screenshots from the solved photo camera (letterboxed to the photo aspect), never overrides a slot the user changed by hand, and aborts if the spec changed under it.
- **The seven round-2 contract fields** (`src/lib/spec/types.ts` + `schema.ts`, all TS-optional / zod-required-with-a-default so an older payload still `safeParse`s; `stripForStrict` drops the default so the model is forced to answer). `runs[].uppers2` + `runs[].uppers2HeightIn` — the second, shorter tier of wall cabinets; `elements[].open` (`BoxOpenEdges`, four booleans, **never a tuple**) + `elements[].openCause` (`'frame'|'occluded'|'both'`) — which edges of a photo box are a CUT; `detected.finishes[].plankRun` (`'toward'|'across'|'diagonal'`, told in the PHOTO's terms); `decor.stools.seatShape` + `.seatColorHex`. `null` on every one of them means "draw what you drew before". Two pure modules own their rules: `src/lib/spec/uppers.ts` (`resolveUppers2HeightIn`, `deriveUppers2`, `TIER1_TARGET_IN` 36, `STACK_MIN_ROW_IN` 45) and `src/lib/spec/photo-box.ts` (`resolveOpen`, `frameOpenEdges`, `FRAME_EDGE_EPS`). `healContract` and `reconcile` both fill them through the same helpers, so the server and the client can never disagree.
- **Stacked uppers**: a run's wall-cabinet row is solved TWICE over the same x extents; `KUpper` carries its own `top` and `tier` (1 = on the counter, 2 = the transom), `KRun.upperSplit` is the rail line (null = one tier), and `millwork.ts` draws a face-frame rail only where both tiers have a box. Read `u.tier` / `run.upperSplit` — never the set of distinct `u.bottom`s, because a hood cabinet legitimately sits on the canopy and gives a stacked row THREE bottoms. The estimator prices tier 2 as its own `cab-upper-stack` line so `cab-crown` and `undercab` cannot double. `layout.ts` also carries the hood safety net (`lib/spec/hood.ts`, and again in `reconcile.ts` before the fit) and CARVES an `appliance-gap` for a built-in that found no void, so a dishwasher is never drawn across a door.
- **Frame truncation**: a box the picture cut is a LOWER BOUND, not a size. `report.ts repairOpen` pushes the photo box's open edges out to the twin's before IoU, centre distance and `proportionError` — overshoot past a cut is free, stopping short still pays — in the loss, the pairing cost and the residuals alike. `fit.ts`'s one-sided `OFF_FRAME` term (weight 0.08, horizontal edges only) charges a twin that stops INSIDE a frame edge the photo says it runs off, using the unclamped `projectElementRaw`; a box open on BOTH sides of an axis is excluded on that axis, which is how the shell planes stay out of it. `capped()` marks a size whose own box is frame-cut `unmeasured`, dropping the ±25% gate, the search bound and the prior's pull together. `buildIsland` slides the body off its declared centre to reach the declared length ONLY when the island's photo box is frame-cut (or there is no island box at all): a fully measured box means the anchor is where the photo put it, and letting it slide there turned `island.offset.x` into a free parameter the fitter wandered on. `KIsland.anchorX/anchorZ` is the declared centre — read that, not `cx/cz`, for anything that must be size-independent.
- **Plank direction**: `FinishObservation.plankRun` is resolved against `detected.camera.lookingAt` into a room-frame boolean and fed to `PBRRecipe.rotate90`; a catalog plank running the other way forces a synthesised custom material. The plank canvas is RECTANGULAR in world terms (`spanM` across the boards, `spanVM` along them) — anything scaling a procedural swatch must use both.
- **The acceptance suite**: `scripts/check-photo-fidelity.ts` turns the client's own sentence into seven groups of measurable assertions over all four kitchen fixtures plus `defaultKitchen`, and prints a per-fixture table. A promise that cannot be met **fails loudly with the number** — never by moving the threshold. A row whose CODE is landed and asserted elsewhere but whose frozen fixture predates it is `pending`, named with the stream or the re-analysis it waits on. It is NOT part of the 14-green `check-*.ts` gate; run it with them anyway.
- Studio photo mode: `photoMatch.ts` (`solvedCameraRig` → `toRig`), the photo overlay with opacity + `O`, "Fit to photo", `Photo match NN%` chip.
- Regression fixtures from real client photos: `scripts/fixtures/client-*.spec.json` (`client-tan` is the tan/oak kitchen this round is about; used by `scripts/check-fit.ts` and `check-photo-fidelity.ts`); `node scripts/e2e-analyze.mjs <photo-url> kitchen out.json` runs analyze → inventory → fit against a running server and writes a localStorage payload for the studio.
- Lighting facts that bit us: three's `RectAreaLight` emits along its LOCAL −Z; interiors use `RoomEnvironment` (photo HDRIs tint ceilings with their floors); metals get `setMetalEnvBoost`; dev hook `window.__manhattanThree = { scene, gl, camera, advance }` (the Browser pane pauses rAF — call `advance()` and `readPixels` to measure).

## Conventions
- Room frame: centred at origin, floor y=0; back wall z=-d/2 (faces +z), front z=+d/2, left x=-w/2, right x=+w/2. `t∈[0,1]` along a wall runs left→right as seen from inside facing that wall (`wallFrame` encodes this — always use it).
- Cabinet/fixture dimensions come from the spec in inches/feet → convert with `inch()`/`ft()`.
- Every user-facing surface must be a `<Surface slot=…/>` so it is clickable + swappable. Trim/fillers/hardware may share the parent slot.
- Design system: the Unifictional theme in its dark mode (same tokens as unifictional.com: near-black `#090909`, near-white `#f5f5f5`, hairline borders, the studio's gold `#c9962e` as the only colour). Tokens/classes in `globals.css` (`.panel`, `.btn .btn-primary .btn-ghost .btn-sm`, `.chip`, `.input`, `.eyebrow`, `.font-display`, colours `bg-bg bg-surface text-ink text-muted text-brass border-border`). Fonts: Oswald (display, always uppercase, no italics), Hanken Grotesk (sans), Space Mono (mono/eyebrows). Every header links back to unifictional.com. Icons: lucide-react.
- Client components need `'use client'`. Never import three/R3F in server components. `next/dynamic` with `ssr:false` for canvases.
- Env: see `.env.example`. Server-only secrets never reach the client. `OPENAI_API_KEY` is the only required key.
- Typecheck with `npx tsc --noEmit`; lint with `npm run lint`.
