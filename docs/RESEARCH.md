# BUILD SPEC — Photo-to-3D Remodel Visualizer + Estimator (v1)

Date: 2026-09-04. Target: Next.js 16 on Vercel Pro. Audience: contractors (kitchen / bath / lot-exterior). Hard product promise: explorable 3D + material swaps + live estimate inside ~60 s of upload.

## 1. Executive summary — what is honestly achievable in 60 s

**What "3D in 60 s" can mean today, ranked by fidelity to the real space:**

| Tier | What the user gets | Latency | Fidelity to *their* room | Swappable? | Cost/job |
|---|---|---|---|---|---|
| **T0 — Procedural digital twin (SHIP THIS)** | LLM extracts a structured `RoomSpec` (walls, cabinet runs, island, counters, windows, fixtures, materials, dimensions) → parametric R3F scene with real PBR materials, orbit/walk camera, click-to-select surfaces | 12–20 s after upload | Layout-accurate, dimension-approximate (±10–15% until user confirms one measurement); *not* photo-identical | Instant (<100 ms, client-side texture swap) | ~$0.03 |
| **T1 — Photoreal "hero" edit** | The customer's own photo re-rendered with the chosen materials (masked edit, geometry preserved) | 15–30 s, parallel with T0 | Photo-identical geometry/lighting | Each swap = one new edit, 10–25 s | $0.05–0.13/edit |
| **T1.5 — Generative walk-around splat (optional, v1.5)** | Gaussian splat of the space from the hero photo(s), rendered in the same three.js scene | ~20 s draft (World Labs), full ~5 min | Real where photographed, AI-imagined elsewhere; splats **cannot** be re-textured | No (regenerate in background after a swap) | $0.12 draft / $1.20 full |
| **T2 — High-fidelity async** | Marble 1.1 Auto Layout on 4–8 same-space photos (2M-splat SPZ + collider GLB), Meshy-7 object scans of a client's fixture, Hover measured exterior takeoff | 5–10 min; Hover 1.5–12 h | Highest | Objects yes; splats no | $1.20–2.80; Hover $39–119 |

**The honest position:** no API on the market reconstructs a *room* or a *house* photorealistically from 1–5 casual photos in 60 s. Object image-to-3D (Meshy-7, Hunyuan3D 3.x, Tripo, TRELLIS.2) turns a kitchen photo into a diorama blob; feed-forward room reconstruction that is commercially licensable (MoGe-2, DA3-Metric, GenWildSplat) needs a self-hosted GPU and yields holes where the camera never looked; World Labs Marble is the only hosted image→explorable-3D API and it hallucinates the unseen parts and takes ~5 min at full quality.

So v1 is a **two-surface product**: the *digital twin* (T0) is the thing you explore and swap in real time and the thing that drives pricing (areas come from its geometry); the *hero photo edit* (T1) is the thing that looks photoreal and closes the sale. They share one `RoomSpec` and one material selection, so a swap updates both — the twin instantly, the photo in ~15 s. Splats (T1.5/T2) are layered on later for "walk around" wow, clearly labelled as partly AI-imagined. This is exactly where competitors are weakest: Hover's interior 3D is measurement-only and its design tool is 2D-from-one-photo; every consumer AI tool is photo-in/photo-out.

**Keys to create now (all justified):** Google AI Studio (Nano Banana 2/Pro — best structure-preserving editor, no key yet), fal.ai (SAM 3 masks at $0.005 + hosted Hunyuan3D fallback), World Labs platform ($5 minimum, for T1.5). Keep using: OpenAI (analysis + gpt-image-2 fallback), Meshy (object scans). Higgsfield: prototyping only until support confirms Cloud-API access to the needed models.

### 2.4 Higgsfield — verdict

- **Official Cloud API** (`api.higgsfield.ai`, `Authorization: Key id:secret`, long-lived keys, sanctioned): the published OpenAPI lists only `/nano-banana` (original), Popcorn, Reve; **but** the spec is account-scoped and incomplete — official JS SDK release notes show `subscribe('nano-banana-pro', …)` and the Python README uses `bytedance/seedream/v4/text-to-image`. **Action:** create a Cloud account, hit `POST /nano-banana-pro` with test creds; if 200/queued, it becomes a sanctioned fallback for edits. No 3D endpoints exist on this surface; do not plan 3D through Higgsfield.
- **CLI / consumer backend / hosted MCP**: exposes everything (nano_banana_pro 2 cr, seedream_v5_pro 3, gpt_image_2 8.5, hunyuan3d 11–19, meshy_v7 38, sam_3_3d 1) but is `/v2alpha`, OAuth-unstable (issues #74/#76/#79), and the July 2026 ToS forbid making Developer Access available to third parties. **Use for internal prototyping and preset pre-generation only; never route customer traffic through the personal Ultra account.** Email support@higgsfield.ai for written confirmation of model enablement + concurrency on the Cloud API.

## 3. Recommended pipeline

### 3.1 Shared timeline (all space types)

```
t0–3s   Browser: HEIC→WebP, downscale ≤2048px, EXIF strip, parallel direct uploads to Vercel Blob (private)
t3s     POST /api/jobs → Postgres row → start(runJob) → return {jobId}; client opens SSE
t3–5s   [step] Luna pre-pass: {space_type, hero_index, style_hint}                       ─┐
t3–20s  [step] Terra RoomSpec extraction (strict JSON)                                    │ parallel
t3–6s   [step] SAM 3 masks for every priced surface on the hero photo (fal, ~1–3 s each)  │
t5–30s  [step] Hero photoreal render from hero photo + default/selected materials         │
t5s     [step] Meshy multi-image-to-3d kickoff IF user attached an "example fixture"     ─┘
t20s    Client: RoomSpec → parametric R3F twin renders (GLB-free, procedural) — user can orbit NOW
t20s    [pure fn] Estimate = Σ surface.area × SKU.unit_cost … (no LLM) → streamed
t30s    Hero render lands → photo tab + parallax 2.5D card
t30–60s Material taps: twin updates instantly; masked edit queued (≤3 concurrent, dedupe on selection hash)
t60–110s Meshy GLB lands → placed in twin at metric scale
bg      Marble draft splat (20 s) → "Walk around" tab; Marble 1.1 full (5 min) if user has ≥4 photos
```

### 3.2 Kitchen

1. **Extraction prompt** asks for: room polygon (ft), ceiling height, wall segments with window/door openings, cabinet runs (start/end wall coords, base/wall/tall, door style, color, hardware), island (dims, seating side), countertop material/edge/thickness, backsplash extent (full-height vs 4-in), floor, appliance slots (range/hood/fridge/dishwasher/microwave with widths), sink type/location, lighting. Every dimension carries `confidence`.
2. **Scale anchor**: assume 36" counter height and 24" base depth; ask the user to confirm ONE known dimension (tape a wall or the island length) → uniform rescale of the spec. Show "±15% until confirmed".
3. **Twin builder** (client): `buildKitchen(spec)` instantiates walls (BoxGeometry, PBR paint), cabinet boxes per run with door style geometry (slab/shaker/raised via extruded frame), counters as extruded polygons following runs (+ island), backsplash as wall-parallel plane behind runs, floor plane, appliances as parametric placeholders (or Meshy GLB / Poly Haven appliance GLBs), windows as cutouts + Lightformer. Each surface gets a stable material slot name: `Countertop`, `Backsplash`, `Cabinet_Base`, `Cabinet_Wall`, `Island`, `Floor`, `Wall_Paint`, `Hardware`.
4. **Photoreal**: hero edit prompt template (roles/change/preserve/integration, one surface per call, restate PRESERVE verbatim). Multi-view: edit hero first; other photos get `[original, approved hero edit, swatch]` refs.
5. **Estimate**: cabinet LF = Σ run lengths; counter sqft = Σ run length × 2.1 ft + island area; backsplash sqft = Σ run length × (18 in or full height); floor sqft = polygon area; + adders (sink/cooktop cutouts, edge profile LF, demo, electrical/plumbing tiers picked by the LLM's `scope_flags`).

### 3.3 Bathroom

Same shape with: fixture slots (vanity width/double, toilet, tub/shower footprint, shower glass type), wet-wall tile extent (walls × height), floor tile, niche count, vanity top material, plumbing-move flag (`fixture_relocated: true` adds $500–1,000 per fixture). Twin materials: `Vanity_Cabinet`, `Vanity_Top`, `Shower_Wall_Tile`, `Floor_Tile`, `Wall_Paint`, `Tub`, `Fixtures_Finish`. Extra estimate lines: waterproofing (60 sqft Kerdi $2.55–3.35k), glass, exhaust fan, toilet.

### 3.4 Lot / exterior

1. Extraction: façade elevations visible (front/side), stories, footprint estimate (ft), roof type/pitch class (low/mid/steep), roof material, siding material + trim, window count/sizes, doors, garage doors, driveway/patio/deck/fence footprint, landscape zones. If a plan/PDF is uploaded, parse it as a second image and prefer its dimensions (`source:"plan"`). If an "example house" photo is given, extract `style_reference` only (never geometry).
2. Twin: massing model (extruded footprint × stories, gable/hip roof from pitch class), façade planes with window/door cutouts, ground plane with zones (driveway, deck, lawn, fence line). Material slots: `Siding`, `Trim`, `Roof`, `Front_Door`, `Garage_Door`, `Deck`, `Fence`, `Driveway`, `Paint_Body`, `Paint_Trim`.
3. Photoreal: Nano Banana Pro for siding/roof (best consistency); "replace only the painted façade surfaces… keep windows, openings, roof edge unchanged".
4. Estimate: wall area = perimeter × wall height × stories − openings; roof squares = footprint × pitch factor (1.05/1.20/1.45) / 100; siding, paint, roofing by area; trim/soffit/fascia LF = perimeter × 2 + openings; deck/fence/driveway by footprint.
5. v2: Hover Complete job for bid-grade takeoff (photos must be taken in Hover's app; 4–12 h, 1.5 h expedited; $39–119) — reconcile the instant estimate on webhook.

### 3.5 How renders and scans layer onto the twin

- **Photo tab**: hero edit + SAM masks make surfaces clickable in the photo; a click selects the same slot in the twin.
- **Twin tab**: R3F scene; optional **camera registration** (LLM-estimated FOV + user drags 3 corners) lets the edited photo be projected as a `MeshProjectedMaterial`-style decal on the twin for a "2.5D" hybrid view (v1.5).
- **Walk tab** (v1.5): Spark `SplatMesh` (Marble SPZ, rotated `[π,0,0]`, scaled by `metric_scale_factor`) sharing the scene with twin meshes; splat = context, twin surfaces = the swappable overlay.
- **Objects**: Meshy GLB (auto_size) dropped into the twin at the fixture slot; its named materials become extra swap slots.

export function KitchenTwin({ spec, selection, onSelect, onSurfaces }:
  { spec: RoomSpec; selection: Record<string, string>; onSelect: (slot: string) => void; onSurfaces: (s: Surface[]) => void }) {
  const mats = {
    Countertop: useMaterial(selection.Countertop), Cabinet_Base: useMaterial(selection.Cabinet_Base),
    Cabinet_Wall: useMaterial(selection.Cabinet_Wall), Backsplash: useMaterial(selection.Backsplash),

    for (const w of spec.walls) {

    }
    for (const r of spec.kitchen.cabinet_runs) {

        <mesh key={`${r.id}-${slot}`} position={[cx + nx * depth / 2, y + h / 2, cz + nz * depth / 2]} rotation-y={-ang} castShadow receiveShadow

    }

const texCache = new Map<string, Promise<THREE.Texture>>()

function tex(url: string, srgb: boolean, repeat: number, gl: THREE.WebGLRenderer) {
  const k = `${url}|${repeat}`
  if (!texCache.has(k)) {
    ktx2 ??= new KTX2Loader().setTranscoderPath('/basis/').detectSupport(gl)
    const loader = url.endsWith('.ktx2') ? ktx2 : new THREE.TextureLoader()

      if (srgb) t.colorSpace = THREE.SRGBColorSpace   // R3F v9: albedo only, manual
      return t
    }))
  }
  return texCache.get(k)!
}

export function useMaterial(sku: string | undefined, surfaceMeters = 2) {

# Completeness critique

- **(a) Not buildable as written with today's keys.** Every "primary" path needs a key you don't have: SAM 3 masks (fal), Nano Banana 2/Pro (Google), Marble (World Labs); the Higgsfield CLI has no 2D segmenter either (`sam_3_3d` emits object GLBs, not masks). Add a feature-flagged "keys-in-hand" profile: OpenAI (Terra/Luna + gpt-image-2 with hard alpha mask) + Meshy only, with the mask source being Terra-emitted per-surface polygons (`surfaces[].mask_polygon`, normalized coords) refined client-side (OpenCV.js GrabCut / draggable vertices). SAM 3 becomes an upgrade when `FAL_KEY` exists.
- **(a) OpenAI image throughput kills §8's "hero + 3 Inspire Me variants in <30 s."** That is 4 gens/job; Tier 1 (5 img/min) serves ~1 job/min org-wide, and Tier 2 is unlikely to cover concurrent users. Generate variants sequentially after the hero, gate them to Pro, and verify gpt-image-2 IPM per tier from the dry run before writing any SLA copy.
- **(a) Higgsfield probe should not spend credits.** The docs reference an `/estimate/{model}` path (`/estimate/higgsfield-ai/soul/v2/...`); use `/estimate/nano-banana-pro` to test routability on a Cloud account. Also fix the naming trap: repo MODELS.md `nano_banana_2` = Nano Banana *Pro*, `nano_banana_flash` = Nano Banana 2, live catalog = `nano_banana_pro`; pin job types from `higgsfield model list --json`, never from MODELS.md.
- **(b) Unverified model/endpoint strings** (absent from the dossier): `gemini-3.1-flash-image`, `gemini-3-pro-image`, `POST /v1beta/interactions`, `thinking_level`, `image_size`, "10 object refs" for NB2 (dossier confirms only Pro's 6 object + 3 style refs, 1K/2K/4K), the NB2/Pro dollar figures, `gpt-image-2-2026-04-21`, `image[]` ≤16, `partial_images`. Resolve ids via each provider's models list at boot, default to `models/{m}:generateContent` + `generationConfig.imageConfig`, and treat `interactions` as experimental.
- **(b) "Gemini has no native mask" is asserted, not verified.** Higgsfield's `nano_banana_flash` exposes `is_inpaint` + `mask`, so the model supports masked inpainting somewhere. Check the Gemini API docs; if a mask input exists, use it and keep the SSIM composite as a second lock.
- **(b) Meshy facts are misattributed.** The dossier says Meshy publishes no latency (the "~1 minute" line is fal's Hunyuan3D page; 30–90 s is third-party). Non-enterprise assets are deleted after 3 days and free-tier outputs are CC BY 4.0: copy every GLB to Blob on completion and only run customer scans on Pro credits.
- **(b) World Labs numbers/shapes drift from the dossier.** Image-input drafts cost 150 + 80–100 credits ($0.18–0.20, not $0.12); multi-image preview is ~2 min (the 20 s figure is text/single-image); Auto Layout requires identical aspect ratio and resolution across photos (your ≤2048-long-edge downscale breaks that for mixed portrait/landscape), ≥1024², no people. `worlds:generate`, `WLT-Api-Key`, and `spz_urls{100k,500k,full}` are not in the dossier (it lists ~2M/~500k exports): verify against the API reference. `SplatLayer` applies `metric_scale_factor` but ignores `ground_plane_offset` (subtract from Y) so the splat floor will not sit at the twin's y=0.
- **(c) The ±15% badge is asserted, never measured.** Build a 20-room ground-truth set (tape-measured walls, runs, island) and report P50/P90 dimensional error per space type; gate the badge text on that number and label totals "rough" until one dimension is confirmed.
- **(c) RoomSpec extraction is the critical path and lands later than t20.** ~1.5K JSON tokens at 84 tok/s ≈ 18 s + TTFT + low-effort reasoning ≈ 22–30 s, and "every key required + null unions" inflates output; `max_output_tokens:2000` also includes reasoning tokens (truncation risk; use ≥4000).
